---
name: product-plan
description: Turn a new product request into a bounded brief, acceptance examples, and registry UI choices before feature work in this starter.
---

Read docs/PRODUCT.md. Fill missing product decisions from the user's request and available material; ask only when a material decision cannot be inferred.

Specify one complete user journey and its observable success/failure conditions. Name required integrations and external side effects. Record the selected official UI block/components and important states in the brief; consult docs/UI.md when selecting them.

Save the next concrete implementation task in docs/WORK.md. Keep the plan proportional to the request. Do not install a speculative database, authentication system, agent framework, or component library merely to complete a checklist.
